# Лабораторная работа 3 — Flutter

Готовое приложение «Мой каталог» для Android. Весь учебный код находится в `lib/main.dart`. Использованы стандартные виджеты Flutter, простые классы, списки, `setState()` и `Navigator`. Единственный дополнительный пакет приложения — обязательный по заданию `fluttertoast`.

## 1. Что реализовано

| Требование | Где и как проверить |
|---|---|
| DefaultTabController, AppBar, TabBar, TabBarView | Главная, вкладки «Список» и «Сетка» |
| 10 элементов ListView | Изначально товары №1–10; прокрутите список вниз |
| ListTile | У каждого товара есть leading, title, subtitle, trailing |
| Toast по нажатию на товар | Сообщение «Вы выбрали: Товар №…» |
| GridView.builder, минимум 6 элементов | Шесть ячеек, каждая со своим исходным цветом, числом и скруглением |
| StatefulWidget и setState | Нажатие делает ячейку зелёной, повторное возвращает исходный цвет |
| Отдельный экран с Card | Кнопка «Карточки» на главной; четыре карточки с локальными PNG |
| Подробности объекта | «Подробнее» открывает описание выбранного товара |
| Drawer с четырьмя пунктами | «Главная», «Профиль», «Настройки», «Выход» |
| Профиль | Учебное имя, email и аватар |
| Настройки | Switch меняет состояние; значение сохраняется при повторном открытии экрана |
| Выход | Toast «Выход из аккаунта» |
| Приветствие | Кнопка «Показать приветствие»: Toast «Hello, Flutter!» |
| Toast ещё в двух местах | Выбор товара, изменение настройки, выход; также добавление товара |
| ThemeData | Единая тема цвета индиго, стили заголовков, отступы и скругления |
| Дополнительное задание | «+» → AlertDialog → название → «Добавить» → новый элемент списка |

В документе есть расхождение: в задании 4 нужны минимум четыре карточки, а в итоговой таблице — одна. Здесь выполнено более строгое условие: четыре карточки. То же относится к уведомлениям: выполнены все отдельные требования, а не только минимум из итоговой таблицы.

Данные хранятся в оперативной памяти. После полного закрытия приложения или Hot Restart список и настройки возвращаются к исходным значениям. Постоянное хранение, авторизация и системные напоминания не входят в задание. Переключатель демонстрирует изменение и передачу состояния; обязательные Toast работают независимо от него.

## 2. Быстрый запуск, если Flutter и эмулятор уже установлены

1. Распакуйте `flutter_lab3.zip`, например, в `C:\flutter_projects\`.
2. В VS Code выберите **File → Open Folder** и откройте папку `flutter_lab3`. Именно в ней должны лежать `pubspec.yaml`, `lib` и `android`.
3. Откройте **Terminal → New Terminal** и выполните:

```powershell
flutter --version
flutter pub get
```

4. Запустите Android-эмулятор через Android Studio → Device Manager → кнопка ▶ у телефона. Дождитесь рабочего стола Android.
5. В VS Code нажмите **Ctrl+Shift+P**, выберите **Flutter: Select Device**, затем Android-эмулятор.
6. Откройте `lib/main.dart` и нажмите **F5**. Если появится выбор конфигурации, выберите Dart & Flutter.

Альтернатива F5 — команда в терминале:

```powershell
flutter devices
flutter run -d emulator-5554
```

`emulator-5554` — пример идентификатора. Подставьте идентификатор Android-устройства из своего вывода `flutter devices`. Не выбирайте Windows, Chrome или Edge: задание проверяется на Android.

При первом запуске нужен интернет для загрузки пакетов и Android-компонентов. Сборка может занять несколько минут. После установки изображения приложения загружаются из проекта и не требуют интернета.

## 3. Установка инструментов с нуля на Windows

### Flutter и VS Code

1. Установите Git for Windows: https://git-scm.com/downloads/win
2. Установите VS Code: https://code.visualstudio.com/
3. В VS Code откройте Extensions (**Ctrl+Shift+X**). Установите расширение **Flutter** от **Dart Code**. Оно также установит расширение Dart.
4. Установите Flutter SDK по официальной инструкции: https://docs.flutter.dev/install/with-vs-code
   Можно использовать **Ctrl+Shift+P → Flutter: New Project → Download SDK**, выбрать доступную папку, например `C:\src\flutter`, и согласиться добавить SDK в PATH. Если SDK уже есть, укажите его существующую папку.
5. Перезапустите VS Code и терминал. Проверьте:

```powershell
flutter --version
flutter doctor
```

Проект подготовлен с Flutter **3.47.4** и Dart **3.13.3**. В `pubspec.yaml` указан Dart `^3.13.3`; используйте Flutter 3.47.4 или более новую совместимую стабильную версию. Dart отдельно устанавливать не нужно: он входит в Flutter SDK.

Если ваша версия старее, обновите SDK:

```powershell
flutter channel stable
flutter upgrade
```

Это обновляет общий Flutter SDK, которым могут пользоваться другие ваши проекты.

### Android SDK

1. Установите Android Studio: https://developer.android.com/studio
2. Запустите его и пройдите мастер первоначальной настройки.
3. На стартовом экране откройте **More Actions → SDK Manager**. Если проект уже открыт, найдите SDK Manager в меню **Tools**.
4. На вкладке **SDK Platforms** установите платформу, которую требует ваша версия Flutter. Если сборка сообщает, например, `android-36`, установите соответствующий Android API 36.
5. В **SDK Tools** проверьте наличие Android SDK Build-Tools, Android SDK Command-line Tools (latest), Android SDK Platform-Tools и Android Emulator. Если сборка запросит NDK или CMake, установите указанную в ошибке версию через SDK Manager.
6. Нажмите Apply, дождитесь установки.
7. В терминале VS Code выполните:

```powershell
flutter doctor --android-licenses
flutter doctor
```

Ознакомьтесь с лицензиями и подтвердите их, если согласны. Для этой работы важны исправные Flutter и Android toolchain. Замечание об отсутствии **Visual Studio** относится к сборке Windows-приложений; Android-приложению она не нужна. **VS Code** и **Visual Studio** — разные программы.

Официальная инструкция Android: https://docs.flutter.dev/platform-integration/android/setup

### Создание Android-смартфона

1. В Android Studio откройте **More Actions → Virtual Device Manager** или **Tools → Device Manager**.
2. Нажмите **Create Virtual Device** / **+**.
3. Выберите категорию Phone и модель, например Pixel 6.
4. Выберите рекомендованный совместимый образ Android. Для большинства компьютеров Intel/AMD подходит x86_64. Если образ не установлен, нажмите Download.
5. Нажмите Next → Finish, затем ▶ рядом с устройством.
6. Дождитесь полной загрузки Android.

Проверка в терминале:

```powershell
flutter emulators
flutter devices
```

Если устройство уже создано, его также можно запустить командой:

```powershell
flutter emulators --launch ID_ЭМУЛЯТОРА
```

Вместо `ID_ЭМУЛЯТОРА` вставьте идентификатор из `flutter emulators`. Идентификатор сохранённого эмулятора и идентификатор запущенного устройства в `flutter devices` могут различаться.

Вернитесь к разделу 2 и запустите распакованный проект. Создавать новый Flutter-проект поверх архива не нужно.

## 4. Какие файлы за что отвечают

- `lib/main.dart` — весь код приложения с русскими комментариями.
- `pubspec.yaml` — версия Dart, зависимость fluttertoast и регистрация изображений.
- `pubspec.lock` — зафиксированные версии пакетов.
- `assets/images/` — четыре простые иллюстрации товаров.
- `android/` — стандартная Android-оболочка, созданная Flutter.
- `test/widget_test.dart` — автоматические проверки взаимодействий.
- `README.md` — эта инструкция.

Не переносите только main.dart без пакета и картинок: используйте проект целиком. Если вставляете код в свой существующий проект, дополнительно перенесите `assets/images/`, добавьте `fluttertoast: 10.0.0` в dependencies и зарегистрируйте изображения:

```yaml
flutter:
  uses-material-design: true
  assets:
    - assets/images/
```

Не создавайте второй раздел `flutter:`, если он уже есть. YAML использует пробелы, а не табуляцию. После изменения pubspec выполните `flutter pub get` и полностью перезапустите приложение.

## 5. Как понять код и объяснить его

`main()` запускает `MyApp`. Он создаёт `MaterialApp`, задаёт название, тему и главный экран.

`HomeScreen` — StatefulWidget: его данные могут изменяться. В `items` хранятся названия товаров, в `selected` — состояние шести ячеек. `setState()` сообщает Flutter, что интерфейс нужно перестроить.

`DefaultTabController(length: 2)` связывает заголовки двух вкладок с содержимым `TabBarView`. `ListView.builder` и `GridView.builder` создают элементы по индексу. Индексы начинаются с нуля, поэтому для номера на экране используется `index + 1`.

При нажатии на ячейку `selected[index] = !selected[index]` меняет false на true или обратно. Выражение `selected[index] ? Colors.green : colors[index]` выбирает текущий цвет.

`Product` — простой класс из четырёх полей. `CardsScreen` показывает товары, а `DetailsScreen` получает выбранный объект через конструктор.

`Navigator.push` открывает экран через `MaterialPageRoute`. `Navigator.pop` возвращает назад или закрывает меню/диалог. На второстепенных экранах есть стандартная стрелка назад в AppBar.

`ProfileScreen` содержит демонстрационные данные. Перед сдачей замените «Студент Flutter» и `student@example.com` своими данными.

`SettingsScreen` использует `SwitchListTile`. Функция `onChanged` передаёт новое значение на главный экран, поэтому оно сохраняется при возвращении в настройки.

`AddItemDialog` читает название из `TextEditingController`. `trim()` удаляет пробелы по краям; пустое название не принимается. После добавления новый товар находится в конце списка. `dispose()` освобождает контроллер при закрытии диалога.

`showMessage` вызывает `Fluttertoast.showToast`. Toast — короткое всплывающее уведомление. На современных версиях Android его оформление выбирает система. Документация пакета: https://pub.dev/packages/fluttertoast

## 6. Что показать преподавателю

1. Запустите приложение, покажите название и две вкладки.
2. Прокрутите список до товара №10, нажмите на товар и покажите Toast.
3. Откройте «Сетка». Нажмите несколько ячеек, затем одну повторно: цвет возвращается.
4. Откройте «Карточки», прокрутите все четыре товара. Нажмите «Подробнее», покажите описание и вернитесь стрелкой назад.
5. Откройте Drawer значком ☰. Покажите четыре пункта.
6. Откройте профиль и покажите имя, email, аватар.
7. Откройте настройки, измените Switch. Покажите сообщение о сохранении. Вернитесь и снова откройте настройки: значение осталось.
8. Выберите «Выход»: появится нужный Toast, приложение продолжит работать.
9. Нажмите «Показать приветствие»: появится «Hello, Flutter!».
10. Нажмите «+». Сначала попробуйте добавить пустое название, затем введите «Мой товар» и нажмите «Добавить». Прокрутите список вниз и покажите новый элемент.

Сдайте исходный проект целиком. Файл APK, если он есть рядом с архивом, удобен для демонстрации, но не заменяет исходники.

## 8. Если что-то не запускается

**flutter не распознаётся.** Проверьте установку SDK и PATH. В PATH должна быть папка `bin` вашего Flutter SDK. Перезапустите терминал.

**No pubspec.yaml file found.** Терминал открыт не в корне проекта. Перейдите в папку, где лежит pubspec.yaml.

**No devices / эмулятор не появился.** Запустите телефон в Device Manager, дождитесь его загрузки и повторите `flutter devices`. Затем выберите его в VS Code.

**Эмулятор не загружается.** Проверьте аппаратную виртуализацию в BIOS/UEFI и настройку ускорения эмулятора по официальной инструкции Android. В Device Manager можно попробовать Cold Boot.

**Не найдены Command-line Tools / не приняты лицензии.** Установите инструменты в SDK Manager и выполните `flutter doctor --android-licenses`.

**Unable to load asset.** Проверьте наличие всех PNG и отступы в assets в pubspec.yaml. Выполните `flutter pub get` и полностью перезапустите приложение.

**MissingPluginException при Toast.** Остановите приложение, выполните `flutter pub get` и запустите его заново именно на Android.

**Версия Dart не подходит.** Проверьте `flutter --version`, обновите Flutter до требуемой версии. Не удаляйте ограничение SDK наугад.

**Ошибка загрузки Gradle/пакетов.** Проверьте интернет и доступ к pub.dev, Google Maven и репозиториям Gradle. Повторите команду после восстановления подключения.

**После переноса проекта остались ошибки сборки.** В корне проекта выполните:

```powershell
flutter clean
flutter pub get
flutter run
```

При ошибке Java/Gradle сначала выполните `flutter doctor -v` и проверьте, какую Java использует Flutter. Для этого проекта рекомендуется Java, поставляемая с актуальной Android Studio. Не меняйте версии Gradle и Android-плагина случайным образом.
