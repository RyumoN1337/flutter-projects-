# Post Explorer — SRS 8

Flutter-приложение просмотра, поиска и создания постов JSONPlaceholder. Интерфейс на русском языке. Проект подготовлен для Visual Studio Code; расширения Dart и Flutter рекомендуются в `.vscode/extensions.json`.

## Запуск

Проверено на установленном Dart 3.13.3. Точную версию Flutter можно узнать командой `flutter --version`.

```sh
flutter pub get
dart run build_runner build
flutter run -d chrome
```

В VS Code: откройте эту папку, выберите конфигурацию **Post Explorer Web** и нажмите F5. Также можно выбрать Android-эмулятор через Flutter: Select Device и запустить `flutter run`. Android и Windows платформы включены; проверенная сборка в этой сдаче — Web. Для Android нужен Android SDK, для Windows — Visual Studio с C++ desktop workload.

```sh
flutter analyze
flutter test --reporter expanded
flutter build web
```

Сгенерированные `*.g.dart` и `pubspec.lock` включены в репозиторий. После изменения аннотаций повторите build_runner. Веб-кэш привязан к origin браузера: для повторного запуска используйте тот же порт, например `flutter run -d chrome --web-port 8080`.

## Архитектура

- `lib/presentation/screens/screens.dart` — список, детали, создание; UI обращается к репозиторию и FeedState, без прямого Dio.
- `lib/presentation/state/feed_state.dart` — ChangeNotifier + Provider, независимые состояния обновления, пагинации, ошибок и кэша. Форма отдельно управляет загрузкой авторов и отправкой.
- `lib/data/repositories/post_repository.dart` — преобразование ошибок, работа с удалёнными данными, чтение/запись кэша и локальных постов.
- `lib/data/remote/post_api.dart` — декларативный Retrofit API и сгенерированная реализация.
- `lib/data/models/models.dart` — Post, Comment, User, вложенная Address; json_serializable с checked-десериализацией, fromJson/toJson.
- `lib/data/local/post_cache.dart` — постоянный JSON-кэш в SharedPreferences, версия пространства ключей v1.
- `lib/core/network/dio_client.dart` — единый Dio, таймауты подключения/приёма/отправки, LogInterceptor в debug и технические заголовки X-Client / X-Request-Id.
- `lib/core/error/app_exception.dart` — connection, timeout, client 4xx, server 5xx, json, unknown. Технические данные выводятся только в debug-лог; UI получает понятный текст.

Dio выполняет HTTP и управляет таймаутами, перехватчиками и отменой. Retrofit генерирует HTTP-клиент по аннотациям. json_serializable генерирует преобразования моделей и проверяет типы полей. Repository отделяет способ получения/хранения данных от интерфейса. Provider связывает состояние с UI.

## Требования задания

| Требование | Реализация |
|---|---|
| GET /posts | Пагинация `_page`, `_limit=10` |
| GET /posts/{id} | Детали поста |
| GET /posts?userId={id} | Отдельный метод authorPosts с пагинацией |
| GET /posts/{id}/comments | Комментарии |
| POST /posts | Валидация, блокировка повторной отправки, показ серверного объекта |
| Дополнительные запросы | GET /users и GET /users/{id}; список пользователей используется для выбора автора |
| JSON | Аннотации, генерация build_runner, вложенная Address, nullable email/address/street/city |
| Пагинация | Автоподгрузка у конца списка, нижний индикатор, ручная кнопка, защита параллельных запросов и дублей ID |
| Ошибка страницы | Данные остаются, кнопка «Повторить», номер страницы повышается только при успехе |
| Фильтры | Поиск title без учёта регистра, userId, все/один автор, сортировка ID вверх/вниз, сброс |
| Область поиска | В интерфейсе явно указано: среди загруженных постов; сортировка также локальная |
| Кэш | SharedPreferences, отдельный ключ каждого автора, свежий результат записывается после успеха |
| Обновление | Pull-to-refresh и кнопка в AppBar |
| Состояния | Loading, Success, Error, Cached, Empty представлены на соответствующих экранах |
| Создание | title 5–100, body 10–1000 после trim; userId из списка; локальные посты сохраняются отдельно |
| Тесты | 14 автономных тестов; реальные Retrofit/Dio с mock-адаптером |
| Дополнительное направление | Отмена устаревшего запроса через CancelToken и проверка поколения запросов |

Поиск локальный и не запускает HTTP-запросы, поэтому отмена нужна при смене автора или обновлении. Поздний ответ предыдущего фильтра не может заменить новый список. Кэш автора также не смешивается с общим списком.

## Поведение кэша и офлайн

При первом запуске показывается индикатор, затем первая страница из сети. При ошибке без кэша остаются сообщение и повторная попытка.

При повторном открытии приложения сохранённая лента видна сразу, с пометкой кэша, пока запрашивается первая актуальная страница. При успешном обновлении лента заменяется новой первой страницей; последующие страницы загружаются заново. При сетевой ошибке последний успешный результат не удаляется. Подгрузка после неудачного обновления начинается только после успешной повторной загрузки первой страницы, чтобы не смешивать разные снимки данных.

Кэшируются также пользователи, загруженные детали и комментарии. Детали ещё не открытого поста используют текст из сохранённой ленты; не загруженные раньше комментарии без сети получить нельзя. Повреждённый кэш игнорируется без падения. Ошибка записи кэша не превращает успешный HTTP-ответ в сетевую ошибку; в таком случае сохранение между запусками не гарантировано, причина остаётся в debug-логе.

В браузере приложение должно сначала загрузиться с локального сервера: кэш данных не означает офлайн-установку/PWA. Чтобы проверить отсутствие внешнего интернета, оставьте локальный сервер доступным. На нативных платформах оболочка установлена на устройстве.

## Созданные посты

JSONPlaceholder возвращает ID 101, но не хранит изменения. Приложение сохраняет ответ отдельно и помечает «создан локально», в том числе после обновления и повторного запуска. Несколько созданных постов могут иметь одинаковый серверный ID 101; это ограничение API, поэтому локальные посты не объединяются по ID. Для них приложение не запрашивает `/posts/101` и комментарии, которых сервер не сохранял. Очередь синхронизации не реализована: офлайн-отправка показывает ошибку и сохраняет заполненные поля формы для повторной попытки.

## Демонстрация преподавателю

1. Первый запуск: видно 10 постов.
2. Прокрутить вниз: следующая страница, без дублей; можно нажать «Загрузить ещё».
3. Выбрать автора 2: показываются его посты; быстро сменить автора, старые результаты не подмешиваются.
4. Ввести часть title, сменить направление ID, нажать «Сбросить».
5. Открыть пост: текст и комментарии; вернуться назад.
6. Создать пост: проверить короткие поля и отсутствие автора, затем отправить корректные данные. Увидеть серверный объект и локальную пометку в списке.
7. После загрузки отключить внешнюю сеть и обновить: сохранённые данные остаются и помечены кэшем; при первом запуске без кэша показана ошибка.
8. Выполнить `flutter test`; показать отчёт и скриншоты из `docs`.
