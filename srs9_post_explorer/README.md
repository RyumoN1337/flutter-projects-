# СРС 9 — Post Explorer

Работа продолжает Post Explorer из СРС 8. Сохранены Retrofit/Dio, кэш, пагинация, фильтры, создание постов и обработка ошибок. Для СРС 9 добавлены собственная launcher-иконка, адаптивная Android-иконка, общий валидатор и проверки реального интерфейса.

## Запуск в Visual Studio Code

Откройте папку `srs9_post_explorer`, выполните:

```sh
flutter pub get
flutter run
```

Выберите Android-эмулятор через Flutter: Select Device. Для Web: `flutter run -d chrome`. Генерация Retrofit/JSON при изменении моделей: `dart run build_runner build`.

## Иконка

Оригинальный знак — карточка поста с лупой: чтение и поиск публикаций. Исходник PNG 1024×1024: `assets/icon/app_icon.png`. Прозрачный передний слой: `assets/icon/app_icon_foreground.png`. Геометрический рисунок воспроизводится скриптом `tools/create_icon.py` (Python + Pillow).

Генерация настроена в `pubspec.yaml`, dev-зависимость `flutter_launcher_icons`:

```sh
dart run flutter_launcher_icons
```

Android и iOS включены, `min_sdk_android: 21`, для iOS удаляется alpha. На Android adaptive icon состоит из тёмно-синего фона и прозрачного переднего слоя; рисунок расположен внутри безопасной области. Также обновлены Web и Windows иконки. Android-манифест использует `@mipmap/ic_launcher`, название приложения — Post Explorer. Фактическая минимальная версия Android определяется также требованиями Flutter и зависимостей, значение генератора не понижает её.

## Widget-тесты

`test/post_screens_test.dart`: 7 тестов. Монтируется настоящее приложение PostExplorer, работают реальные экраны, Provider, навигация и валидаторы. Только репозиторий заменён контролируемой реализацией без сети.

1. Главный экран: заголовок, поле поиска, фильтр автора, кнопки и посты.
2. Ввод запроса скрывает неподходящий пост; «Сбросить» очищает поле и восстанавливает результаты.
3. Нажатие «По ID» меняет порядок карточек.
4. Неизвестный запрос показывает Empty-состояние.
5. Нажатие карточки открывает детали и комментарии; Back возвращает список.
6. Кнопка создания открывает настоящую форму; пустые поля показывают ошибки, отправки нет.
7. Заполненные поля и выбор автора позволяют отправить пост; во время ожидания кнопка блокируется, повторного запроса нет; ответ сервера отображается, кнопка возвращает к списку.

14 тестов СРС 8 сохранены в `test/srs8_regression_test.dart` (прежнее имя widget_test.dart было неточным: там использовались test(), не testWidgets()). Итого 34 теста.

```sh
flutter test test/post_validator_test.dart
flutter test test/post_screens_test.dart
flutter test
flutter analyze
flutter build apk --debug
```

## Ответы на контрольные вопросы

1. Launcher Icon — значок приложения в списке приложений и на домашнем экране устройства.
2. flutter_launcher_icons генерирует наборы иконок необходимых размеров для платформ из одного изображения.
3. Настройки находятся в pubspec.yaml, в секции flutter_launcher_icons.
4. Unit Test проверяет отдельную функцию или класс, например PostValidator.title.
5. Unit Test проверяет логику, Widget Test строит интерфейс и проверяет отображение и взаимодействие.
6. expect(actual, matcher) сравнивает результат с ожидаемым условием; несовпадение проваливает тест.
7. test() регистрирует тест логики с названием и функцией проверок.
8. testWidgets() регистрирует UI-тест и передаёт WidgetTester для построения виджетов, ввода и нажатий.
9. flutter test запускает автоматические тесты проекта и сообщает об успехах и ошибках.
10. Тестирование до публикации обнаруживает ошибки и регрессии, снижает риск поломки пользовательских сценариев.
