# TaskFlow — практическое задание № 10

Полностью локальное приложение Flutter/Dart для управления проектами и задачами. Данные хранятся в SQLite через Drift. Интерфейс на русском языке, адаптирован для телефона и широкого окна. Основная проверенная платформа — Android.

## Открытие в Visual Studio Code

Откройте `TaskFlow.code-workspace` либо эту папку через **File → Open Folder**. Расширения Dart и Flutter указаны в рекомендациях проекта. Выберите Android-устройство в нижней панели VS Code и нажмите **F5**.

```powershell
flutter pub get
flutter emulators --launch flutter_emulator
flutter run -d emulator-5554
```

Идентификатор эмулятора на другом компьютере можно узнать командами `flutter emulators` и `flutter devices`. Проект проверен на Flutter 3.47.4 / Dart 3.13.3. Для Windows нужны Visual Studio Build Tools с компонентом Desktop development with C++; на данном компьютере их нет. Web не включён: используется файловый SQLite и локальные вложения.

## Первый запуск

1. В разделе **Участники** добавьте пользователей с именем и уникальным email. Дата регистрации устанавливается автоматически.
2. В верхней панели выберите пользователя, от имени которого выполняются действия. Это локальная модель действующего пользователя для учебного приложения, без сетевой авторизации.
3. Создайте проект, откройте **Участники и роли**, добавьте пользователей и назначьте Owner / Admin / Member. Один пользователь может состоять в нескольких проектах.
4. Создайте задачу. В списке исполнителей доступны только участники выбранного проекта. Укажите дедлайн, приоритет и статус.
5. Откройте задачу нажатием на карточку: здесь доступны редактирование, статус, Undo, комментарии, вложения и история.
6. Нажатие на пользователя открывает его задачи; кнопка «Задачи» проекта открывает задачи этого проекта. Фильтры можно прокручивать горизонтально на телефоне. Пагинация — по 25 записей.
7. **В корзину** скрывает задачу. В разделе **Корзина** можно восстановить её или удалить окончательно с подтверждением.

Права удаления комментариев проверяются в Repository, а не только видимостью кнопки. Роли участников сохраняются и редактируются; отдельная матрица полномочий ролей в задании не задана.

## Архитектура

| Слой | Файлы | Назначение |
|---|---|---|
| Database | `lib/database/schema.drift`, `app_database.dart` | 7 таблиц, PK/FK/UNIQUE/CHECK, индексы, миграция, файловое подключение |
| Model | `lib/model/models.dart`, сгенерированный `app_database.g.dart` | Статусы, приоритеты, фильтры, ошибки, типизированные Drift-модели и companions |
| Repository | `lib/repository/task_repository.dart` | Все SQL-запросы, транзакции, бизнес-ограничения, файлы |
| State Management | `lib/state/app_state.dart` | ChangeNotifier: текущий пользователь, раздел, фильтры, страницы |
| Presentation | `lib/presentation/` | Material 3, формы, списки, статистика, карточка задачи |

SQL не выполняется внутри Widget. Реактивные запросы Repository используют `customSelect(..., readsFrom: ...).watch()`. Операции записи уведомляют Drift через `updates`; экраны обновляются автоматически. Дата для просрочки дополнительно пересчитывается раз в минуту.

## Принятые правила

- Незавершённые — `todo` и `inProgress`. `cancelled` не занимает лимит и не считается завершённой. Процент проекта — `done / все не удалённые задачи × 100`; пустой проект — 0%.
- Дедлайн — календарная дата в локальном часовом поясе, без времени. Просроченными считаются незавершённые задачи с датой меньше сегодняшней.
- Удаление проекта каскадно удаляет его задачи, комментарии, метаданные вложений, историю и участников. Диалог предупреждает о безвозвратности. Удаление задачи из обычного списка всегда мягкое.
- Удаление пользователя допускается только при отсутствии незавершённых задач. В завершённых задачах исполнитель становится NULL, а авторские имена в комментариях/истории сохраняются снимками. Удаление участника проекта также блокируется его незавершёнными задачами.
- Поиск воспринимает `%`, `_` и кавычки буквально, использует параметризованные SQL-запросы. SQLite `lower()` игнорирует регистр ASCII; для кириллицы вводите соответствующий регистр.
- Постоянная база `taskflow.sqlite` и копии вложений лежат в `getApplicationSupportDirectory()`, а не в кэше выбора файлов. Перезапуск не стирает данные. Папка `reports` относится только к тестам.

## Проверка и сборка

```powershell
flutter analyze
flutter test --reporter expanded
dart run build_runner build
flutter build apk --debug
```

Generated-код уже включён в проект; перегенерация нужна после изменения схемы. `pubspec.lock` фиксирует версии зависимостей. Debug APK предназначен для учебной установки; для публикации требуется собственная подпись.

Результаты проверки находятся в `reports/tests.txt`, `reports/analyze.txt`, `reports/benchmark.json`. Нагрузочная база `reports/benchmark.sqlite` поставляется вместе с исходниками и пересоздаётся **только** нагрузочным тестом. Основная БД приложения им не затрагивается.

## Нагрузочный эксперимент

Запрос объединяет фильтрацию по проекту и статусу, поиск, сортировку по дедлайну и пагинацию. 20 прогревочных и 200 измеряемых итераций. Сравниваются одинаковые данные и результаты; индексы задач временно удаляются и восстанавливаются. Без индекса план использует SCAN + временное B-tree; с индексом — SEARCH по `idx_tasks_project_status`. Числа зависят от оборудования и нагрузки; точный результат последнего запуска записан в JSON.

Документация, использованная при разработке: [Drift custom queries и watch](https://drift.simonbinder.eu/sql_api/custom_queries/), [миграции](https://drift.simonbinder.eu/migrations/api/), [SQLite на нативных платформах](https://drift.simonbinder.eu/platforms/vm/).
